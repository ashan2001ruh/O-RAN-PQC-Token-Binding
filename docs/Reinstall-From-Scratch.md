# Reinstall Everything From Scratch

Every command needed to go from a blank Ubuntu VM to the complete testbed: the OSC
Near-RT RIC, the classical token-binding stack, the post-quantum stack, and the
Kyverno-injected sidecars with two xApps onboarded through `dms_cli`.

Run the commands in order. Each phase ends with a check; do not continue past a failed
check. Commands run as the normal user (`pasindu` on the reference VM), never as root
unless `sudo` is written.

**Reference environment** (what this was built and verified on):

| | |
|---|---|
| OS | Ubuntu 20.04.6 LTS, kernel 5.15 |
| VM | 4 vCPU, 5.6 GB RAM, 40 GB disk, VMware NAT |
| Kubernetes | v1.28.11 (installed by the RIC deployment scripts) |
| Container runtime | containerd + Docker 20.10 |
| Go | 1.27.1 in `~/tools/go` |
| OpenSSL | 1.1.1f (the system one; it cannot do ML-DSA, which is why the PKI is generated by a Go tool) |

Total time from blank VM: roughly 90 minutes, most of it the RIC install.

## Phase 0: VM and network

The RIC binds its control plane to one IP address and does not tolerate that address
changing. Decide the address **before** installing and keep it.

```bash
ip -4 addr show
```

The reference VM has `192.168.80.135` on `ens33` under NAT, and the RIC was installed
against `192.168.1.134` from an earlier bridged configuration. That is why the node keeps
the old address as a permanent secondary alias. If you are installing fresh, skip this and
just use the current address consistently.

**If you are rebuilding a node whose RIC was installed on a different address**, add the old
one back as a `/32` alias, permanently:

```bash
nmcli con show
sudo nmcli con mod 'Profile 2' +ipv4.addresses 192.168.1.134/32
sudo nmcli con up 'Profile 2'
ip -4 addr show ens33          # both addresses must be listed
```

Swap off and kernel modules, which kubeadm requires:

```bash
sudo swapoff -a
sudo sed -i '/ swap / s/^/#/' /etc/fstab
sudo modprobe br_netfilter
echo 'br_netfilter' | sudo tee /etc/modules-load.d/k8s.conf
```

**Check**

```bash
free -m | awk 'NR==3 {print "swap total:", $2}'   # must print 0
ip -4 addr show ens33 | grep inet
```

## Phase 1: The OSC Near-RT RIC

Follow the deployment guide you already use:

<https://github.com/pasindu-janith/o-ran-sdl-security-documentation/blob/main/OSC-RIC%20setup.md>

That guide installs Docker, containerd, Kubernetes, Helm, the local chart repositories and
the RIC platform charts. In outline:

```bash
sudo apt-get update && sudo apt-get install -y git
git clone https://gerrit.o-ran-sc.org/r/it/dep
cd dep
git submodule update --init --recursive --remote
cd bin
sudo ./install_k8s_and_helm.sh          # Kubernetes 1.28 + Helm + containerd
sudo ./install_common_templates_to_helm.sh
cd ../RECIPE_EXAMPLE/PLATFORM
# edit example_recipe.yaml so ricip and auxip are YOUR node address
cd ../../bin
sudo ./deploy-ric-platform -f ../RECIPE_EXAMPLE/PLATFORM/example_recipe.yaml
```

Give the normal user a kubeconfig, which everything below assumes:

```bash
mkdir -p ~/.kube
sudo cp /etc/kubernetes/admin.conf ~/.kube/config
sudo chown "$(id -u):$(id -g)" ~/.kube/config
echo 'export KUBECONFIG=$HOME/.kube/config' >> ~/.bashrc
export KUBECONFIG=$HOME/.kube/config
```

**Check** — every platform pod Running, and the namespaces present:

```bash
kubectl get pods -n ricplt
kubectl get ns | grep -E 'ricplt|ricxapp|ricinfra'
```

Expect `e2term`, `e2mgr`, `a1mediator`, `rtmgr`, `submgr`, `appmgr`, `dbaas` all Running.

> **If the RIC comes up Pending/NotReady after a reboot or a network change**, the usual
> cause is the control plane address having moved. `sudo crictl ps` and
> `journalctl -u kubelet -n 50` will show connection refused against the old address.
> Restore the address as in Phase 0 and `sudo systemctl restart kubelet`.

## Phase 2: Node tooling

### 2.1 Go 1.27

Required: `crypto/mldsa`, `crypto/mlkem` and `crypto/hkdf` are standard library only from
1.27. Nothing in this project builds on an older Go.

```bash
mkdir -p ~/tools && cd ~/tools
curl -fsSLO https://go.dev/dl/go1.27.1.linux-amd64.tar.gz
tar -xzf go1.27.1.linux-amd64.tar.gz
echo 'export PATH=$HOME/tools/go/bin:$PATH' >> ~/.bashrc
export PATH=$HOME/tools/go/bin:$PATH
go version          # go version go1.27.1 linux/amd64
```

### 2.2 Local image registry

The onboarded xApps pull from it, so it must survive reboots.

```bash
sudo docker run -d --restart=always -p 5000:5000 --name local-registry registry:2
curl -s http://127.0.0.1:5000/v2/_catalog        # {"repositories":[...]}
```

### 2.3 ChartMuseum

`dms_cli` pushes the chart it builds to `CHART_REPO_URL`. The binary ships with the RIC
install; it is not started by it.

```bash
mkdir -p ~/chartstorage
cat > /tmp/chartmuseum.service <<'EOF'
[Unit]
Description=ChartMuseum local Helm chart repository
After=network.target

[Service]
User=pasindu
Environment=STORAGE=local
Environment=STORAGE_LOCAL_ROOTDIR=/home/pasindu/chartstorage
Environment=PORT=8090
Environment=ALLOW_OVERWRITE=true
ExecStart=/usr/local/bin/chartmuseum
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
sudo cp /tmp/chartmuseum.service /etc/systemd/system/chartmuseum.service
sudo systemctl daemon-reload
sudo systemctl enable --now chartmuseum

echo 'export CHART_REPO_URL=http://localhost:8090' >> ~/.bashrc
export CHART_REPO_URL=http://localhost:8090
```

Replace `pasindu` with your user name in both `User=` and `STORAGE_LOCAL_ROOTDIR`.

### 2.4 dms_cli

Installed by the RIC deployment; install it directly if missing:

```bash
command -v dms_cli || {
  git clone https://gerrit.o-ran-sc.org/r/it/dev ~/it-dev
  sudo pip3 install ~/it-dev/xapp_onboarder
}
```

**Check**

```bash
go version
curl -s localhost:8090/health                    # {"healthy":true}
curl -s http://127.0.0.1:5000/v2/_catalog
dms_cli health                                   # or: dms_cli --help
helm version --short
```

## Phase 3: The project

```bash
cd ~
# copy the xapp-token-binding directory onto the node, e.g.
#   scp -r "xapp-token-binding" pasindu@<node>:~/
cd ~/xapp-token-binding
chmod +x scripts/*.sh build/*.sh ca/scripts/*.sh
```

Review the single configuration file. Everything else is derived from it; no hostname,
port or DN is written anywhere else.

```bash
$EDITOR config/testbed.env
```

The values you might change: `RICSEC_NAMESPACE`, `XAPP_NAMESPACE`, `CLUSTER_DOMAIN`,
`LOCAL_REGISTRY`, `CHART_REPO_URL`, the certificate lifetimes, and the ML-DSA parameter
sets.

`sudo` over a non-interactive SSH session cannot prompt, so give it an askpass helper
before any target that builds images:

```bash
printf '#!/bin/sh\necho YOUR_SUDO_PASSWORD\n' > /tmp/askpass.sh
chmod 700 /tmp/askpass.sh
export SUDO_ASKPASS=/tmp/askpass.sh
```

Then append `SUDO='sudo -A'` to any `make` line that builds images. On an interactive
terminal you can omit all of this.

**Check** — offline unit tests, no cluster needed:

```bash
make unit
```

All packages must report `ok`.

## Phase 4: Classical stack

One command builds the PKI, the binaries, the images, and deploys the CA, Keycloak, the
shim and the two demo xApps:

```bash
make SUDO='sudo -A' up
```

What it runs, in order: `pki`, `build`, `images`, `namespaces`, `trust`, `deploy-ca`,
`deploy-keycloak` (which imports the realm), `deploy-shim`, `bootstrap-xapps`,
`deploy-xapps`, `wait`, `host-env`.

Keycloak takes several minutes on this VM. If the rollout times out, it is almost always
memory; check with `kubectl -n ricsec describe pod -l app=keycloak | tail -20`.

**Check**

```bash
kubectl -n ricsec get pods          # ric-ca, keycloak, pq-shim all 1/1 Running
kubectl -n ricxapp get pods         # xapp-a, xapp-b all 1/1 Running

make verify-ca                      # milestone 1: issues a leaf, verifies the chain,
                                    #             proves the bootstrap credential is one-time
make verify-keycloak                # milestone 2: token over mTLS carries cnf.x5t#S256
make test                           # 46 security cases, all must pass
```

`make test` writes `results/security-tests.csv`. It drives the classical path and will
refuse to run against a post-quantum deployment.

Optional measurements:

```bash
make bench                          # results/bench.csv, results/bench-env.csv
```

## Phase 5: Post-quantum stack

Switches the CA, the shim and the xApps to ML-DSA credentials and ML-DSA-signed tokens.
The PKI generated in Phase 4 already contains both branches, so nothing is regenerated.

```bash
make SUDO='sudo -A' pq-up
```

**Check**

```bash
kubectl -n ricxapp get cm xapp-token-binding -o jsonpath='{.data.PQ_MODE}{"\n"}'   # true
kubectl -n ricsec get pods

make run-a                          # Method A end to end, post-quantum
make run-b                          # Method B, with certificate rotation
make run-c                          # Method C, DPoP
```

Each walkthrough prints the enrolment, the Keycloak token, the shim upgrade and the
resource call, and ends with the binding it verified. Look for `alg=ML-DSA-65`,
`kty=AKP` and `X25519MLKEM768` in the output.

To go back:

```bash
make SUDO='sudo -A' classical-up
```

## Phase 6: Sidecars, Kyverno and onboarding

Requires Phase 5: the tunnel authenticates peers with ML-DSA certificates and the sidecar
refuses to start without one.

```bash
make PQ_MODE=true SUDO='sudo -A' sidecar-up
```

What it runs, in order:

| Step | What it does |
|---|---|
| `build`, `images` | adds `ricsec/xapp-sidecar:0.1.0` to containerd |
| `demo-app-image` | pulls stock busybox, pushes it to `127.0.0.1:5000` |
| `kyverno` | installs the Kyverno admission controller (chart 3.3.9, admission controller only) |
| `sidecar-policy` | applies the ClusterPolicy and the two sidecar Services |
| `bootstrap-sidecar-xapps` | mints one-time SMO bootstrap credentials for both xApps |
| `onboard-xapps` | `dms_cli onboard` then `dms_cli install` for `xappc` and `xappd` |

If the realm predates the two sidecar clients:

```bash
REPLACE=1 make PQ_MODE=true import-realm
```

**Check**

```bash
make sidecar-status                 # both pods 2/2 Running
make sidecar-logs                   # one line per authorized connection
```

In the logs, each accepted connection must show the binding that was checked:

```json
{"msg":"egress_authorized","binding":"x5t#S256","token_alg":"ML-DSA-65","kex":"ML-KEM-768"}
{"msg":"ingress_authorized","binding":"jkt","client_id":"xapp-sidecar-d"}
```

The unmodified applications must show traffic in both directions and both protocols:

```bash
kubectl -n ricxapp logs -l pq.oran/sidecar=xapp-sidecar-c -c xappc --tail=8
```

```
[http-out] calling the peer xApp through the sidecar
[http-in] hello from xappd, served over the post-quantum tunnel
[rmr-out] sending an RMR message through the sidecar
[rmr-in] RMR:xappd:hello
```

Fail-closed check — a connection that is not a tunnel must never reach the application:

```bash
kubectl -n ricxapp run pq-probe --rm -i --restart=Never \
  --image=127.0.0.1:5000/oran/busybox:1.36 --command -- \
  sh -c 'echo NOT-A-PQ-HANDSHAKE | nc -w 5 xapp-sidecar-d-sidecar.ricxapp.svc.cluster.local 4570'
make sidecar-logs | grep ingress_failed
```

## Teardown

Remove only what this project deployed; the RIC is untouched:

```bash
make sidecar-down        # onboarded xApps, ClusterPolicy, Services, bootstrap secrets
make down                # the ricsec namespace and everything labelled part-of=xapp-token-binding
make clean               # build outputs, keeps out/pki
```

Kyverno, ChartMuseum and the registry are shared infrastructure and are left alone. To
remove them too:

```bash
helm uninstall -n kyverno kyverno && kubectl delete ns kyverno
sudo systemctl disable --now chartmuseum
sudo docker rm -f local-registry
```

To wipe the PKI as well and start completely fresh, `rm -rf out/` before Phase 4. Every
certificate, including the SMO root, is then regenerated.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `make images` fails with `sudo: a terminal is required` | non-interactive SSH | set `SUDO_ASKPASS` and pass `SUDO='sudo -A'` (Phase 3) |
| `error loading config file "/root/.kube/config"` | `KUBECONFIG` unset in the make shell | `export KUBECONFIG=$HOME/.kube/config` |
| Keycloak rollout times out | memory pressure, probe timeouts | check `kubectl -n ricsec describe pod -l app=keycloak`; the probe timeouts are already raised to 10-15 s |
| `403 bootstrap_credential_reused` | two pods started with the same one-time credential | `make bootstrap-xapps` (or `bootstrap-sidecar-xapps`) then redeploy; the deployments use `strategy: Recreate` to prevent overlap |
| `make test` fails 38 of 46 cases | classical suite against a PQ deployment | `make classical-up` first; current builds detect this and exit with a message |
| Token rejected although the deployment looks right | `PQ_ISSUER` and the deployed ConfigMap disagree | `make PQ_MODE=true show-config` and compare with `kubectl -n ricxapp get cm xapp-token-binding -o yaml` |
| Run script reports `token_key_unavailable`, kid not in JWKS | deployed mode and script flag disagree | `kubectl -n ricxapp get cm xapp-token-binding -o jsonpath='{.data.PQ_MODE}'` and match it |
| `dms_cli onboard` says `Could not consume arg --schema_file_path` | the flag is spelled `--shcema_file_path` in `xapp_onboarder` | use that spelling; `scripts/onboard-sidecar-xapps.sh` already does |
| `INSTALLATION FAILED: cannot re-use a name that is still in use` | previous Helm release still present | `dms_cli uninstall --xapp_chart_name=<name> --namespace=ricxapp`, then reinstall |
| Sidecar pod stuck `0/2`, log says `no identity certificate` | CA or Keycloak not ready, or bootstrap secret missing | check `kubectl -n ricxapp get secret | grep bootstrap`; the sidecar retries enrolment for 150 s |
| Sidecar exits with `the sidecar tunnel requires PQ_MODE=true` | classical deployment | `make pq-up` first |
| xApp pod Running but no traffic | the peer sidecar Service has no endpoints | `kubectl -n ricxapp get endpoints | grep sidecar`; the Service selects on the `pq.oran/sidecar` label Kyverno adds |

## What lives where

| Path | Contents |
|---|---|
| `config/testbed.env` | the only place hostnames, ports, DNs, lifetimes and algorithms are written |
| `out/pki/` | the generated PKI, classical and ML-DSA branches (keep this to keep your CA) |
| `out/bootstrap/` | one-time bootstrap credentials, regenerated per deployment |
| `out/host.env` | environment for tools run on the node, written by `make host-env` |
| `results/` | `security-tests.csv`, `bench.csv`, `bench-env.csv` |
| `docs/Implementation-1..6` | every source file with the reasoning behind it |
| `docs/xApp-Token-Binding-Setup.md` | the operator-facing guide this runbook condenses |
